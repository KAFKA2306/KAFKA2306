## Principles

- 一次情報・取得時点・入力へ戻れる形でデータを扱う
- current / snapshot / estimate / generated を混同しない
- failure / unknown / unverified を正常値で埋めない
- implementation / CI / deployment / production を別々に検証する
- 同じ責務のauthority、workflow、config、documentationを増やさない
- 標準機能を優先し、不要なものは削除する

## Repository boundary

このrepositoryの責務はGitHubプロフィールの入口だけです。portfolioの状態管理は各owner repository、GitHub、deployment、productionへ置きます。
